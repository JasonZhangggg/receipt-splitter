# Everyone with the link has equal access, except to payment handles

There are no accounts and no host key. Anyone with a Split's link can edit its Items, prices and Adjustments, add Participants, and Claim any Item for anyone, the Host included. We chose simplicity over control because a Split is shared by a group of friends: to protect against mistakes, it keeps a recent-changes list with undo, and the Total check catches bad prices. The one exception is the Host's payment handles. They are entered when the Split is created and can only be changed from the device that created it, because an edited handle would send everyone's money to someone else.

A Split has no verification beyond the link, because it is between friends. Any device can take any name with **That's me**, and nothing checks who asks. The pick is not recorded in History. Only the device that picked a name, or the device that picked the Host, can record or clear that name's Payment, and a Payment cannot be reverted from History. The Host can do it because the money reaches them, so they check friends off from Payments, and History shows who did. The check in `recordPayment` and `clearPayment` is the `payerOnly` refusal in `src/core/operations.ts`, and the takeover is the `pick` operation with `takeOver` in the same file. The payer-only rule stops honest mistakes, such as marking the wrong person paid. It is not a security boundary, because any device can take the name first.
