# Scan

The Host reads a Receipt on the home page `/`. Items are fixed on the Split page by tapping a line, so home shows the editor only when the read left something a Split refuses. A tap on the hero opens the photo picker. On a desktop, an image dropped anywhere on the page or pasted from the clipboard is read too, and a file that is not an image gets the one line "That file is not a photo." Drop and paste read a photo only on the empty page. On the read state a dropped file changes nothing, and a Host replaces the Receipt with the camera button on the receipt card. While OCR runs, the slip turns into a skeleton with seven lines that darken one at a time over a progress bar, under the title **Reading receipt**. The read state shows the compact receipt card: the thumbnail, the file name, the Item count, the total, and **Replace receipt**. Below 900 px the card stands centered above the sheet with a 116 by 148 px thumbnail. From 900 px it is one row in the page column. A tap on the thumbnail opens the photo viewer. When the read found no Items, or an Item with no name, or an amount over the limit, the row card sits above the editor with editable Items, Subtotal, the other Adjustments, one Tip line, and the Total, and the editor stays through edits and reloads until a new read. **Create split link** stays off with one short reason until the Receipt has named Items and the Host has a name. With no Payment handle it stays on, and a tap moves focus to the first handle field. A failed Total check blocks nothing and shows a quiet note instead. The draft lives in local storage, so a reload keeps it. RS-9 gives the enabled action its handler.

## Sub-features

- `scan-input` opens the picker with `accept="image/*"` from the hero, reads a dropped or pasted image, and refuses any other file with one line in the Toast. Photos decode with `imageOrientation: "from-image"`, so an EXIF-rotated phone photo reads upright.
- `scan-reading` shows the skeleton slip, **Reading receipt**, and a progress bar that fills over the model download, then OCR. With motion on, each line reaches full ink 150 ms after the one above it, in a 1.6 s loop. Under reduced motion the lines hold still, the bar has no transition, and `document.getAnimations()` is empty. The state ends when the Items show.
- `scan-card` is the compact card. The Example has no photo, so its card shows the receipt glyph and has no **View receipt photo**. A reload keeps the card but not the photo, which lives only in the page's memory.
- `scan-viewer` opens the photo the Host scanned in a dialog named for the file. Below 900 px it fills the screen on a dark ground with **Close photo**, the file name, and **Replace receipt** across the top. From 900 px it is a 540 by 640 px frame over the scrim with **Close photo** beside it. Escape, a click on the scrim, and **Close photo** close it. It fades and scales in from 0.96 over 240 ms and out over 180 ms, and under reduced motion it only fades. It lives in `src/ui/photo-viewer/` for V2-6b.
- `scan-editor`, shown only when the read left something a Split refuses, shows each Item's name and price as text fields, an x button per row, **Add item**, the Subtotal, each Adjustment with its own x, the Tip with a dotted underline and a pencil, and the Total. Every edit reruns the Total check. A row the check names, or a price the Host retyped while the check fails, gets the yellow highlight and the price label ", check this price". A 0-cent Item shows as 0.00. An Item a discount took below zero shows "Its discount was more than its price." An OCR price over `MAX_CENTS` reads 0.00 with "Could not read this price."
- `scan-tip` reads the tip from the receipt's tip lines as one line, $0.00 when the receipt prints none. A tip edit moves the Total by the same amount and never changes the Total check.
- `scan-manual` opens the same editor empty, under the row card, a Tax line at $0.00, and an editable Total, when OCR fails or finds no Items.
- `scan-reason` puts one reason with the yellow highlight above a disabled **Create split link** in the read state: "Add an item.", "Name every item.", or "Add your name.". The empty and reading states show no reason. With no Payment handle there is no reason, and a tap on **Create split link** focuses the handle field.
- `scan-mismatch` puts a muted note with no highlight above an enabled **Create split link** while the Total check fails: "Items are $0.50 short of the subtotal.", "Items are $0.50 over the subtotal.", "Tax and charges are $0.61 short of the total.", or, on a typed Receipt, "Items are $18.00 over the total."
- `scan-draft` keeps the Receipt, the tip, the Payment handles, and the names in local storage under `receipt-splitter:draft`. A reload during a read starts the Receipt over and keeps the handles and names. Replacing the Receipt keeps the handles and names.
- `scan-offline` keeps a scan working offline once the model is cached. `public/sw.js` answers from Cache Storage only while the browser is offline, and the page asks it to keep `/`, the entry, the fonts, and the worker script. `sw.js` keeps only same-origin files on its own allowlist, never `/api`, `/parties`, or `/s/`. The OCR worker keeps the ORT JavaScript files with the runtime and the models.
- `scan-bundles` reads a group of Items under a $0.00 header as one Bundle when a later discount's label echoes the header's name, prints a percent, and that percent of the Items right under the header equals the discount, as Topgolf's "Beer Bucket Discount (10%)" does. The Bundle holds only those Items. A discount with no percent, or whose percent matches no run of Items under the header, stays on the whole receipt. The header is the Bundle's name and not an Item, and the discount is a `bundleDiscount` Adjustment that names the Items. On home the discount shows as an Adjustment row. Deleting a Bundle's Item drops it from the Bundle, and deleting its last Item drops the discount. A $0.00 header that no discount closes stays an Item. The created Split holds the Bundles and is stored at `schemaVersion` 2. A Split without a Bundle is stored at version 1.
- `scan-example` fills the draft with SRD receipt 1040 as its checked label reads, named "Example receipt", and keeps the Payment handles.
- `scan-route` is `POST /api/scan`, which reads a receipt on the server (ADR 0008). No page calls it before V2-7b. The body is JSON, `{ "photo": "data:image/jpeg;base64,...", "ocrLines": ["..."] }`, with an `origin` header equal to the site's own origin. It answers 403 `{ "refused": "origin" }` for any other origin or none, 413 `bodyTooLarge` over 1 MiB, 400 `rejected` for a photo that is not a JPEG data URL or a bad body, 503 `unavailable` without the `OPENROUTER_API_KEY` secret, 429 `rateLimited` or `dailyLimit` with `retry-after`, 502 `unreadable` when no pass gives a usable reading, and 200 with the reading: `items` (name, price after the discounts printed under it, quantity, details, discounts), `bundles` (name, Item indexes, discounts), `adjustments`, `subtotal`, `total`, and `check` (`passed`, `gaps`, and `problems` when it fails). A 200 carries `x-scan-cost` in dollars and `x-scan-passes`.
- `scan-limits` allows one address 6 scans a minute and 30 a UTC day, and all addresses 2,000 a UTC day, apart from the create limits. The values are the `SCAN_PER_MINUTE`, `SCAN_PER_DAY`, and `SCAN_DAILY_CAP` vars in `wrangler.jsonc`.
- `scan-passes` reads with pass 1 on the first host in `SCAN_PASS1_HOSTS`, retries once on the second when the call fails, runs past `SCAN_PASS1_TIMEOUT_MS`, or comes back empty, and runs pass 2 on `SCAN_PASS2_HOSTS` only when the check fails. Each scan logs one `"event":"scan"` JSON line with each call's host, time, tokens, cost, and outcome, and never the photo, the OCR lines, or a reply's text.
- `scan-harness` is `bench/scan/run.mjs`, which posts each fixture in `bench/scan/fixtures/` to a running route and prints one table scored by `bench/scan/score.mjs`.

## How to get to it (user POV)

- Open `/` on a phone, tap **Add receipt**, and take or choose a photo.
- Open `/` at 900 px or wider, and click **Drop a receipt**, drop an image on the page, or paste one.
- Tap **Example** at the top right of the empty page, at 768 px or wider.
- In the read state, tap the camera button on the card to replace the Receipt, or the thumbnail to see the photo.

## Driving it with verify.mjs

Preconditions:

- `verify.mjs doctor --port 8811` reports `"ok":true`.
- `<out>` is the lane's output folder, as defined in [README.md](./README.md).

`verify.mjs drive` loads one route and cannot choose a file, so every flow past the empty page runs through `e2e/scan.spec.ts`. Stop the lane's `launch` first, because the spec starts its own server on `PORT`.

- **Read SRD receipt 1040.** `PORT=8812 npx playwright test e2e/scan.spec.ts -g "chosen through the picker"` picks `bench/data/srd-1040.jpg`, sees **Reading receipt**, then the card with "srd-1040.jpg", "5 items", and "$28.04", no Item list, the five Items in the stored draft, no reason, and **Create split link** on. A tap on it focuses the Venmo handle, and a handle then brings up "Add your name."
- **Failing Total check.** `-g "fails the Total check"` reads `e2e/fixtures/srd-1040-no-sprite.jpg`, whose Sprite line is painted out, sees "4 items", the muted note "Items are $2.50 short of the subtotal.", and creates the link.
- **Viewer.** `-g "photo viewer"` opens the photo from the thumbnail at 390 px and closes it with **Close photo** and Escape, closes it with a scrim click at 1280 px, replaces the photo with the card's camera, and checks the Example card has nothing to open.
- **Type it.** `-g "failed read"` reads `e2e/fixtures/blank.png`, gets the empty editor and "Add an item.", types two Items and a Total, and gets an enabled action.
- **Desktop input.** `-g "1280 px"` refuses a dropped PDF with one line, then reads a dropped image and a pasted image.
- **Topgolf Bundles.** Choose `e2e/fixtures/topgolf-synthetic.png` through the picker in a Playwright script against a `launch`ed port. The card reads "topgolf-synthetic.png / 9 items / $207.29". The stored draft holds nine Items (Gameplay, then two runs of Michelob Ultra, Guinness, High Noon Pineapple, and High Noon Watermelon, with Guinness ×3 in the first run and Guinness ×2 and Watermelon ×2 in the second) and two "Beer Bucket Discount (10%)" rows at -4.51 and -4.63, with no mismatch note. No "Beer Bucket" Item is stored. The image is drawn from `src/parse/fixtures/topgolf.tsv` by `e2e/fixtures/make-fixtures.py` and holds no payment lines. Never use the real Topgolf photo in a committed test.
- **EXIF.** `-g "EXIF"` reads `e2e/fixtures/srd-1040-exif-rotated.jpg`, whose pixels lie sideways with EXIF orientation 6, as the same five Items in the stored draft.
- **Reading state.** `-g "reading state"` holds the dictionary download for 3 s, checks that the seven lines darken in order, and that reduced motion runs no animation.
- **Reload and offline.** `-g "reload keeps the draft"` scans, edits, waits for the service worker, goes offline, reloads, and scans again. `-g "payment apps and names"` switches to Cash App, adds Venmo with **+**, adds two names, removes one, and reloads.
- **Sheet.** `-g "the sheet"` drags the grab handle a short way and watches the panel spring back, catches it during the spring, and fills it until its content scrolls. In `e2e/home.spec.ts`, `-g "the phone panel|no way to pay"` drags it from beside the payment row, checks that the action moves with it with no gap, taps the handle field with a small wander, and taps **Create split link** with no handle.
- **Screens.** For a screenshot of a state, run the spec with `--trace on` and save a frame, or use a short Playwright script against a `launch`ed port, as `/tmp/swarm-RS-7/owner/shots.mjs` does.

### The scan route and its harness

Preconditions:

- `.dev.vars` in the worktree root holds the key. Write it without printing it: `node -e 'const fs=require("fs");const k=fs.readFileSync(process.env.HOME+"/.config/receipt-eval/env","utf8").match(/OPENROUTER_API_KEY=(\S+)/)[1];fs.writeFileSync(".dev.vars","OPENROUTER_API_KEY="+k+"\nSCAN_DEBUG_HEADERS=true\n",{mode:0o600})'`. `SCAN_DEBUG_HEADERS=true` makes the route send `x-scan-cost` and `x-scan-passes`, which `run.mjs` reads. It is `false` in `wrangler.jsonc`, so production never sends them. `.dev.vars` is gitignored, and `.dev.vars.example` names the key with an empty value. Never commit, print, or log the key.
- `verify.mjs launch --port 9211` reported `"ok":true` after `.dev.vars` was written. Wrangler reads `.dev.vars` only at start.
- Live scans cost money. Check the balance before and after a run with `node ~/receipts-eval/credits.mjs`.

- **Score the fixtures.** `node bench/scan/run.mjs --url http://localhost:9211 --runs 3` prints the table and exits 1 below `bench/scan/fixtures/floor.json`. t1 is the Topgolf receipt drawn from `src/parse/fixtures/topgolf.tsv`, and its row should show both Bundles right.
- **Score the operator's receipts.** `node bench/scan/run.mjs --url http://localhost:9211 --runs 3 --dir ~/receipts-eval --truth ~/receipts-eval/truth.json --only r1,r2,r3,r4,r5,r6,r7,r8` reads `ocr/<id>.json` for the OCR lines. Report the table by receipt id only (preferences 53).
- **Retry on the second host.** Add `SCAN_PASS1_TIMEOUT_MS=1` to `.dev.vars`, relaunch, and scan once with `--runs 1 --only t1`. `.verify/9211/wrangler.log` shows a `"event":"scan"` line whose first two calls are pass 1 with `"outcome":"timeout"`, the second on the second host. Remove the line and relaunch afterwards.
- **A refusal.** `curl -s -X POST http://localhost:9211/api/scan -H 'origin: https://other.example' -d '{}'` prints `{"refused":"origin"}`.

## Gotchas

- OCR takes about 0.4 to 1 s once the models are cached, so the reading state can be gone before a slow assertion runs. Hold a model download with `page.route` to keep it on screen.
- `react-native-web` compiles `animationKeyframes` only inside `StyleSheet.create`. An inline keyframe style renders with `animation-name: none`.
- The OCR worker stays alive for 10 s after the last scan, then the page terminates it. A scan inside that window reuses the engine.
- The service worker answers only while `navigator.onLine` is false, so Playwright routes still see every online request. Offline it serves only what its caches hold, so a route it never kept, such as `/s/<id>`, fails as it would without it.
- To switch the service worker off in production, set `KILL = true` at the top of `public/sw.js` and deploy. Browsers fetch `sw.js` past the HTTP cache (`_headers` serves it `no-cache`), and the new worker deletes every cache and unregisters. The page registers it again on each load and it removes itself again, so keep `KILL` set until a fixed worker ships.
- Local storage carries the draft between loads in one browser context. Start each check in a fresh context, as Playwright does per test.
- The Example has no photo, so its card shows the receipt glyph instead of a thumbnail.
- Below 768 px there is no **Example** link. A phone-width spec widens the page to 768 px for the tap with `openExample` in `e2e/files.ts`.
- `e2e/fixtures/make-fixtures.py` writes the fixtures it derives from `bench/data/srd-1040.jpg`, and draws the scan fixtures in `bench/scan/fixtures/` from their invented TSVs.
- The scan limits count per address in the lane's own Durable Object storage, and every local scan comes from `localhost`. A seventh scan in a minute gets 429, and the 31st in a day too. `run.mjs` waits out a `retry-after` of 65 s or less. For a harness run of more than 30 scans, add `SCAN_PER_MINUTE=100` and `SCAN_PER_DAY=1000` to `.dev.vars` and relaunch. Leave them out when checking the limits themselves.
- `wrangler dev` reads `.dev.vars` and the `wrangler.jsonc` vars only at start. Relaunch after changing either.
