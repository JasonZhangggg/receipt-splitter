## How we work (operator-set; full text in preferences.md)
- **Owners and pushes.** One fresh agent owns each PR, in its own worktree. Owners commit locally and never push. The root verifies the exact SHA, then pushes once, opens the PR, and merges on green CI with `--merge --match-head-commit`. Never weaken a test to get green. The root doesn't edit product code itself.
- **Verify budget.**
  - About 30 minutes of test runs per PR.
  - At most about 10 to 15 logic mutants.
  - One live pass with screenshots.
  - Perf is size plus LCP over 3 interleaved loads.
  - UI PRs also run the Playwright motion suite.
  - At most **2 agents run full test suites at once**, and they wait until `uptime` load is under 10, because higher load caused false timeouts.
- **Context.**
  - PRs are sized so the owner stays under about 300k tokens.
  - Past about 400k, write a handoff and give fix rounds to a fresh fixer.
  - All agents run at **medium effort**: `effort: medium` in the agent definitions, and say it in general-purpose briefs.
  - Agents **must not use spawn_task chips**. They list follow-ups in their report.
- **Operator updates.** Post only on big changes (a merge, a deploy, a FAIL, a decision needed, a blocker) or when the operator runs `/status`. The audit tick runs silently. Re-arm it as a dynamic `/loop`, about 30 minutes, after the clear.
- **Shell and privacy.**
  - Never `cd ...;`. Use `git -C` or `&&`.
  - The real receipt photo and its OCR under `/tmp/redesign/` and `/tmp/v2/v2-2/live/` hold payment data. Never commit or share them.
- **Restarts.** Session restarts kill background agents. After a restart, check each worktree for commits and uncommitted work before redispatching.
